# Commits, PRs, and merge policy

## Base branch

Base ref: `$(git symbolic-ref --short -q refs/remotes/origin/HEAD || echo origin/main)`. It falls back to `origin/main` when `origin/HEAD` is unset (a repo made with `git remote add`, not `git clone`). Each Bash call may run in a fresh shell, so never keep it in a variable: paste the substitution into the same command that uses it. Branch off, diff against, and open PRs to that ref; wherever a skill says `<base>`, use it.

## Commits

- One line. No body. No trailers (no Co-Authored-By).
- Follow the repo's existing style; otherwise `type: subject` (fix, feat, chore, docs, refactor, test, perf).
- Never force-push.

## PR / MR

- Title: `type: subject`, at most 70 characters.
- Body: English, at most 300 words, sections in this order: Problem / Cause / Change / Evidence / Not touched / Risks.
- Last line links the issue when one exists: `Closes #<n>` (GitHub) or `Fixes TON-<n>` (Linear; the Linear GitHub integration closes the issue on merge).
- No AI attribution anywhere: commits, PR bodies, comments, code. PR bodies and comments carry no AI footer (such as "Generated by ..."); if a tool adds one, edit the body or comment to remove it.
- Contributor mode uses its own MR description (see [contributor-mode.md](contributor-mode.md)).

## Merge policy

- Merge needs an allow rule for `gh pr merge` / `glab mr merge` (the auto-mode classifier refuses merges without one). Without that rule, or when `gh pr merge` / `glab mr merge` cannot run (for example in a cloud session), stop at the approval and hand the merge to the user with the PR/MR link. Never merge through REST: it can fall back to the default body with its trailers.
- Merge only when the PR head equals the SHA in the latest `APPROVED (round <n>) at <sha>` comment ([review.md](review.md)). A newer head needs a fresh check first. Pass that SHA to the merge so a late push makes it fail: `--match-head-commit <sha>` (`glab`: `--sha <sha>`).
- Squash merges pass an explicit subject and an empty body, which drops the Co-authored-by and Claude-Session trailers the default body collects: `gh pr merge --squash --match-head-commit <sha> --subject "<PR title> (#<n>)" --body ""`.
- L1 with the allow rule: merge once the PR has the approval above and CI is green. Use `gh pr merge --auto` with the flags above (or `glab mr merge --auto-merge --squash --sha <sha>`). If auto-merge is disabled on the repo, wait with `gh pr checks --watch`, then merge. If the repo has no CI checks at all, run the full test suite locally, paste the result in the PR, and merge only if it passes.
- L2+: merge only after the user explicitly approves in the conversation, and only with the allow rule above.
- Pushing needs the user's OK unless the lane's merge policy already covers it (L1 with the allow rule does). One batch-level OK at the throughput checkpoint covers the pushes and PRs of every ticket in that batch; do not ask again per push.
- Contributor mode never merges; maintainers do.

## Attribution settings

Claude Code adds its own trailers and footers unless the repo's `.claude/settings.json` turns them off: an empty string hides each one, and `sessionUrl: false` drops the Claude-Session trailer and the PR session link. Cloud sessions read this file only in single-repo sessions, so the rules above apply either way.

```json
{
  "attribution": {
    "commit": "",
    "pr": "",
    "sessionUrl": false
  }
}
```

Merge the `attribution` key into an existing file and keep its other keys. The file must be tracked: if `.gitignore` ignores `.claude/`, replace that line with `.claude/*` and `!.claude/settings.json`.
